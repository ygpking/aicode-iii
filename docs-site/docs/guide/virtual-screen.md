# 虚拟屏调试

虚拟屏让 AI 在**一块独立于你物理屏的显示屏**里打开 App、读取界面、点击输入，全程**不占用你的屏幕**：不开浮层、不抢焦点、不进你的最近任务。你可以一边刷微信，AI 一边在虚拟屏里走一遍注册流程。

它补的是本地容器和 Shizuku 都补不上的那一块：**真正把 App 点开、看真实界面**。容器里跑不了 Android 应用，Shizuku 只能发命令、看不到界面。

## 能做什么

| 能力 | 本地容器 | Shizuku | 虚拟屏 |
| --- | :---: | :---: | :---: |
| 运行 Android App | ✗ | ✗ | ✓ |
| 读取界面内容（文本/控件/坐标） | ✗ | ✗ | ✓ |
| 点击、输入、滑动 | ✗ | 有限（`input`） | ✓ |
| 操作期间占用你的屏幕 | — | ✗ | ✗ |
| 需要 root | 否 | 否 | 否 |

AI 拿到一个名为 `virtualScreen` 的工具，动作有七个：

| 动作 | 作用 |
| --- | --- |
| `open` | 开屏并启动指定包名的 App |
| `dump` | 读取当前界面（结构化文本：可见文本、控件、坐标） |
| `click` | 按文本或控件 id 点击 |
| `input` | 向输入框写入文本 |
| `swipe` | 滑动 |
| `status` | 查看会话与依赖状态 |
| `close` | 关闭会话并回收（同时强制停止目标应用） |

典型流程是 `open → dump → click/input → dump 确认 → close`。

## 两个前提

### 1. Shizuku 已授权

建屏这一步走 Shizuku，**root 与 adb（uid 2000）两种授权都可以**。配置方式见 [Shizuku 执行后端](/guide/shizuku)。

`virtualScreen` 与 `Shizuku` 同级，属高危工具：每次调用都会弹授权确认，不支持「始终允许」。几块屏、开哪个 App 都由你逐次放行。

### 2. 开启 AiCode 的无障碍服务

建屏本身不需要无障碍，但**读界面和点击需要**。未开启时 `open` 仍会成功，`dump`/`click`/`input`/`swipe` 会返回明确提示。

开启路径：**系统设置 → 无障碍 → 已下载的服务 → AiCode III**。

系统不允许应用自行开启无障碍服务，必须你手动打开。这是刻意的：无障碍能读取全系统界面内容，权限太重，不能由应用替你决定。

## 用法示例

「帮我在设置里确认一下有没有『开发者选项』这个入口」

AI 会依次调用：

```
virtualScreen(action="open", packageName="com.android.settings")
virtualScreen(action="dump")                    # 读到界面文本
virtualScreen(action="swipe", y1=1800, y2=600)  # 往下翻
virtualScreen(action="dump")
virtualScreen(action="click", text="关于手机")
virtualScreen(action="close")
```

整个过程你的屏幕上什么都不会发生。

## 边界：它不是沙箱

这一点必须说清，避免误判风险：

- **不是数据隔离**。虚拟屏只是把界面渲染到另一块屏，跑的还是**同一个已安装的应用、同一份数据**。在虚拟屏里登录，该应用在本机的登录状态就变了。需要真正隔离的环境，见 [容器与镜像](/guide/container)。
- **只读虚拟屏**。无障碍服务在代码层面只遍历目标 `displayId` 的窗口，不读取你当前正在用的屏幕内容。
- **锁屏时也能用**。虚拟屏被创建为「自成显示组且始终解锁」，因此**你的手机锁屏或熄屏时，
  AI 仍能在虚拟屏里正常打开并操作 App**——这也是它最有价值的场景：你锁屏、把手机放着的时候让 AI 干活。
- **关闭时强制停止目标应用**。否则系统会把它的任务残留搬到你的主屏、污染最近任务。代价是：若该应用你本来就在用，`close` 会把它一起停掉。

## 已知限制

以下是当前版本的实测结论与**尚待验证**的项，如实列出：

- **不保证所有 App 都能正常显示**。部分应用（含带 DRM 保护的内容、某些游戏）在虚拟屏上可能黑屏或拒绝渲染。
- **`swipe` 的滑动距离与惯性**按像素给出，与具体应用的列表行为可能有偏差。
- **部分机型（如 MIUI）的后台限制**可能影响长时间会话，建议用完即 `close`。
- **无障碍服务可能被系统自动停用**。实测重装或强制停止应用后，已开启的无障碍会掉掉，
  需到系统设置里重新开启。
- **操作会触发系统显示器增删**。极少数情况下，个别机型在增删显示器瞬间可能出现物理屏短暂闪烁，属系统侧的重配置行为。

**已实测可用**（含中文）：开屏、读界面、点击、输入、滑动。

## 常见问题

**`open` 报「Shizuku 未就绪」**

按 [Shizuku 执行后端](/guide/shizuku) 确认已安装 → 服务已启动 → 已授权。设备重启后 Shizuku 服务通常需要重新启动。

**`dump` 报「无障碍服务未开启」**

到系统设置里手动开启 AiCode III 的无障碍服务（见上文前提 2）。开启后无需重启应用。

**`click` 找不到目标**

先 `dump` 看界面上实际有什么。常见原因：文本是包含匹配但写成了全串、界面还没加载完（`dump` 时加 `waitReady`）、或该文本所在的控件不可点击。`dump` 输出里带坐标，可用 `click(bounds="left,top,right,bottom")` 兜底。

**`close` 之后目标应用被停掉了**

这是设计行为（见「边界」一节）。AI 会在关闭会话时一并 `force-stop`，避免任务残留到你的最近任务里。
