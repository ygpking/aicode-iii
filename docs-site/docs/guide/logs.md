# 日志与故障排查

App 出问题时，日志是最直接的线索。「设置 → 日志」可以直接在应用内看。

## 应用内看日志

进去默认定位到今天的日志，页面上能做这些事：

- **日志等级**：顶部设置行显示当前等级，点击从底部面板选择（Verbose / Debug / Info / Warn / Error / None）。遇到 bug 时建议调成 `Debug`，日常保持 `Info`。正式版默认是 `Info`，过滤掉调试噪音。
- **切换文件**：点「日志文件」行从底部弹出日期列表，默认选中今天。
- **搜索与复制**：关键字实时过滤，右上角一键复制当前筛选结果。
- **彩色分级**：Verbose 灰、Debug 蓝、Info 绿、Warn 橙、Error 红。
- **单行复制**：点任意一行复制这条完整日志（含时间、等级、来源）；长按弹菜单可以选复制范围——本条、本条及堆栈、或只要消息内容。
- **实时滚动**：默认开启，每 3 秒自动刷新并跟随最新；关掉后停止刷新，保持你手动浏览的位置。

为了避免大日志卡顿，应用内只显示当前文件在筛选条件下的最后一部分，完整文件要去文件系统看。

## 日志文件在哪

```
/storage/emulated/0/Android/data/com.aicode/files/logs/
```

不需要 root 权限，用手机自带的文件管理器就能打开。

工作区项目文件与 AI 配置存放在应用私有目录，普通文件管理器看不到，访问方式见[文件浏览与代码编辑](/guide/files#工作区文件在手机上的位置)。

## 事件轨迹（排查界面异常的专用记录）

除了上面的普通日志，App 还会另外记一份「事件轨迹」，位置在：

```
/storage/emulated/0/Android/data/com.aicode/files/traces/
```

它和普通日志看的东西不一样：普通日志记的是「程序内部发生了什么」，轨迹记的是「这次对话一步步变成了什么样子」——模型什么时候开始/结束输出、调了哪个工具、工具成功还是失败、界面什么时候从「思考中」变成「回复中」。遇到**聊天气泡显示不对、状态卡住不消失、消息顺序错乱**这类问题时，把这份文件发给开发者最有用。

打开后每行格式大致是这样：

```
16:51:39.654  s=9ed520ee t6 #96 ←#95  UI  尾巴 busy=true reasoning=false ...
16:51:39.761  s=9ed520ee t6 #99 ←#95  EVENT  tool_finished Bash id=... 失败 结果=127字 原因摘要=...
```

看的时候认这几个字段就行：

- 开头的 `s=` 是哪次对话，`t6` 是这次对话的第几轮。
- `#96` 是这一行的序号，`←#95` 表示「这一行是由第 95 行引起的」——顺着箭头往前往回读，就能知道事情是怎么一步步发展下来的。
- 行中间的文字（如 `EVENT`、`UI`）表示这是哪一类记录，后面是具体内容。

工具执行失败的行会直接带上失败原因，不用再去别处找。

这份记录**默认就开着**，不需要去设置里打开；它只记「节点的变化」，不会把 AI 吐的每一个字都写进去，所以文件不会失控地长大。如果你在设置里把日志等级选成 `None`（完全关闭日志），它也会一起停。

文件按天分，超过一定大小会自动存档，只保留最近几天。它的占用会显示在「设置 → 存储空间」的「日志」一项里，想立即腾空间就在那里点「清理日志」。

## 按 MCP 名称过滤

排查 MCP 连不上的问题时，进「设置 → MCP 服务器」，编辑某个服务器后点右上角的日志按钮，会跳到日志页并自动按这个服务器名过滤（页面顶部有过滤徽章，可一键清除）。列表页右上角的日志按钮则是看全部日志。

## 崩溃了怎么办

App 遇到未捕获的异常**不会直接闪退**，而是全屏显示一个崩溃错误页：

- 页面展示崩溃时的版本、设备、时间和完整堆栈。
- 点「复制错误信息」可以复制完整的崩溃报告（含堆栈和日志文件路径），直接粘贴发给开发者就行，不用自己翻日志。
- 可以选「重启应用」回到主界面，或者「退出应用」完全退出。

崩溃日志同样会落盘到上面那个 `logs/` 目录。

## 长任务切后台被中断怎么办

如果 AI 执行长任务（如编译、深度代码审查）或终端运行耗时命令时切到后台经常被杀掉，请前往「设置 → 软件权限」开启**后台运行保活**、**忽略电池优化**与**自启动管理**，详见[软件权限](/guide/app-permissions)。
