## 一、先看清一个关键事实

`docs-site/docs/guide/error-codes.md` 被**两个分支同时修改**，但它们**不是并列关系**：

| 分支 | error-codes.md | 关系 |
| --- | --- | --- |
| `docs/error-codes-tool-layer` | 144 行（123 个码，**未收敛**） | `fix/trace-format-and-codes` 的**真子集** |
| `fix/trace-format-and-codes` | 144 行（114 个码，**已收敛**） | 包含上面那份内容 + 收敛改动 |

**实测**：两者 `diff` 仅 **5 处差异**，全部是错误码收敛带来的替换。
**结论：不要合并 `docs/error-codes-tool-layer`**——它的内容已被 `fix/trace-format-and-codes` 完全包含。
若两个都合，Git 会在该文件上报 `CONFLICT (content)`（已用 `git merge-tree` 验证）。

## 四、合并分支时不要踩的坑

1. **不要用 `git add docs/`**：仓库里有若干**既有的未跟踪文件**（`docs/缺陷排查-*.md`），
   一把梭会被误纳入提交。只 add 你实际改动的文件。
2. **合并后跑迁移对账**：`python3 scripts/check_migrations.py`（本轮未动 schema，预期直接通过）。
3. **`fix/trace-format-and-codes` 的文档是超集**：若先合了 `error-codes-tool-layer`，
   再合它会冲突；正确做法是**跳过前者**。
4. **三个脚本不进 APK**：`scripts/` 只被构建期任务引用（如 `check_migrations.py`），
   不影响产物；但改了 `app/src/main/**` 必须跑冒烟编译。

## 五、合并后的收尾核对

```bash
git switch main && git pull
python3 scripts/check_migrations.py                     # 迁移对账
./gradlew :app:testUniversalDebugUnitTest               # 单测（PRoot 下预期 4 例环境失败）
./gradlew :app:assembleUniversalDebug                  # 冒烟编译
git branch --merged main                                # 确认已合分支
git branch -d <已合分支> && git push origin --delete <已合分支>
```
